## 1. 文档说明

### 1.1 目的

定义「微光」产品的功能需求、业务规则与非功能目标，作为架构设计、数据库设计、接口设计以及开发测试的基线。

### 1.2 范围

- **覆盖**：产品定位、角色权限、用户故事、功能清单、业务规则、非功能需求、版本规划。
- **不覆盖**：技术选型与实现细节（见架构设计文档）、表结构（见数据库设计文档）、接口定义（见接口设计文档）。

### 1.3 术语

| 术语 | 说明 |
|---|---|
| 帖子 Post | 用户发布的图文内容 |
| Feed 流 | 按时间/兴趣组织的内容列表 |
| 弹幕 | 内容/直播间上实时滚动的文字 |
| 秒杀 Flash Sale | 限时限量的抢购活动 |
| 幂等 | 同一操作多次执行与一次执行结果一致 |
| 热度分 | 用于热榜排序的综合分值 |

## 2. 产品概述

### 2.1 一句话定位

面向 18–30 岁年轻人的「图文种草 + 实时互动 + 限时好物抢购」兴趣内容社区，AI 贯穿内容生产与治理。

### 2.2 背景与目标

- **背景**：年轻人既有内容分享与获取需求，又有实时互动与"蹲好物"的消费习惯；当前市面上的内容社区（纯内容）与电商产品（纯交易）相互割裂。
- **目标**：构建"边逛内容边抢好物"的一体化社区；同时作为个人求职项目，深度展示高并发、缓存、分布式与 AI 工程能力。

### 2.3 目标用户

| 角色 | 特征 | 核心诉求 |
|---|---|---|
| 内容创作者 | 18–30 岁，爱分享 | 低门槛发布、获得曝光与互动 |
| 内容消费者 | 爱刷种草内容 | 快速发现兴趣内容、参与互动、蹲好物 |
| 运营/管理员 | 平台方 | 管理内容、发起秒杀活动、内容治理 |

### 2.4 核心价值与差异化

- **记录与发现**：图文种草 + 推荐 Feed。
- **热闹的互动**：点赞 / 评论 / 弹幕实时互动。
- **边逛边抢**：限时秒杀，社区即集市。
- **AI 降门槛**：自动打标签、评论情感分析、智能摘要。
- **差异化**：社区与秒杀打通形成闭环 + AI 贯穿全流程。

## 6. 关键业务规则

### 6.1 点赞

- 一人一赞，重复点赞幂等；点赞/取消操作原子化。
- 计数由 Redis 维护，异步落库，点赞数并发安全。

### 6.2 秒杀（核心难点）

- 活动窗口外不可抢购；单用户限购 N 件。
- **防超卖**：Redis 预扣减 + Lua 原子操作。
- **异步下单**：MQ 削峰，消费者幂等。
- **超时关单**：未支付订单超时自动关闭（延迟消息），回补库存。
- **最终一致性**：订单与库存一致（详见架构文档）。

### 6.3 Feed 流

- 关注流采用**推拉结合**：大 V 用"拉"，普通用户用"推"（按粉丝量阈值切换）。
- 时间线分页采用游标 / 时间戳。

### 6.4 热榜

- 热度分 = 加权(点赞 / 评论 / 浏览) + 时间衰减。
- ZSet 维护，定时 / 增量更新。

### 6.5 缓存一致性

- 读多写少数据缓存；更新采用"先更库再删缓存 / 延迟双删"。
- 防穿透（布隆过滤器）、防击穿（互斥锁/逻辑过期）、防雪崩（过期时间随机）。

### 6.6 鉴权与安全

- 登录接口限流；接口鉴权（JWT + 拦截器）；敏感操作（秒杀）严格校验。

### 6.7 幂等

- 点赞、抢购、MQ 消费、支付回调等均需幂等。

## 7. 非功能需求（NFR）

### 7.1 性能

- 首页 Feed 接口 P95 < 200ms。
- 秒杀核心接口 QPS 目标 ≥ 1000（JMeter 压测验证）。
- 弹幕消息延迟 < 200ms。

### 7.2 并发

- 支持秒杀瞬时高并发；热点数据缓存。

### 7.3 可用性

- 核心接口限流 / 降级（微服务阶段接入 Sentinel）；缓存 / DB 故障兜底。

### 7.4 安全

- 验证码安全、接口防刷、越权校验、XSS / SQL 注入防护。

### 7.5 可扩展性

- 单体阶段模块清晰，预留微服务拆分边界（账号 / 内容 / 互动 / 秒杀 / AI）。

### 7.6 可观测性

- 结构化日志、关键指标监控（后期接入）。

## 8. 版本规划

- **MVP（第一阶段，单体）**：账号、内容、互动、Feed、秒杀、AI 打标签/情感分析、后台基础。
- **后续**：搜索（ES）、智能推荐、消息通知、数据看板。
- **演进（第二阶段）**：微服务拆分 + 网关 + 注册配置 + 熔断降级 + 分布式事务 + 链路追踪 + Docker/K8s。
