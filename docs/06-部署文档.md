## 1. 部署拓扑

```
Windows 开发机（192.168.157.x）
┌──────────────────────────────────────────┐
│  Spring Boot backend :8080               │
│  Apifox / 浏览器 / JMeter                 │
└───────────────┬──────────────────────────┘
                │ 通过 VM IP 访问（firewalld 只放行 192.168.157.0/24）
┌───────────────▼──────────────────────────────────────────────┐
│ CentOS 7 VM  192.168.157.129                                 │
│ Docker 24.0.9 + Compose v2                                   │
│                                                              │
│  glimmer-net（bridge，172.28.0.0/16，gateway 172.28.0.1）     │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐        │
│  │ mysql:3306   │  │ redis-core   │  │ redis-cache  │        │
│  │ 业务库       │  │ 6379         │  │ 6379→宿主6380│        │
│  └──────────────┘  └──────────────┘  └──────────────┘        │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐        │
│  │ rabbitmq     │  │ elasticsearch│  │ kibana(可选) │        │
│  │ 5672 / 15672 │  │ 9200 + IK    │  │ 5601         │        │
│  └──────────────┘  └──────────────┘  └──────────────┘        │
└──────────────────────────────────────────────────────────────┘
```

- 容器之间用**服务名**互访：`mysql`、`redis-core`、`redis-cache`、`rabbitmq`、`elasticsearch`。
- Windows 宿主机通过 `192.168.157.129:<宿主机端口>` 访问；不能用 `localhost`。
- 两个 Redis 容器内都监听 6379，宿主机分别映射为 **6379（core）/ 6380（cache）**。

## 3. 版本锁定

| 组件 | 锁定版本 | 说明 |
|---|---|---|
| Docker Engine | **24.0.9** | CentOS 7 / 内核 3.10 / cgroup v1 兼容性更稳；不要盲目升最新 |
| containerd.io | 随 Docker CE 24.0.9 依赖 | 由 yum 解析 |
| Docker Compose | **v2.29.7**（静态二进制或 plugin） | 需要支持 `name`、`depends_on.condition`、`mem_limit` |
| MySQL | **8.0.39** | DDL 使用 `CHECK`、`utf8mb4_0900_ai_ci`、`DATETIME(3)` |
| Redis | **7.2-alpine** | core / cache 同镜像，不同启动参数 |
| RabbitMQ | **3.13.7-management** | 管理台 + 延迟插件 |
| RabbitMQ Delayed Message Plugin | **3.13.0** | 必须与 RabbitMQ 3.13.x 匹配 |
| Elasticsearch | **8.15.0** | 单节点、关闭 security（内网开发） |
| IK 分词 | **8.15.0** | **必须与 ES 版本完全一致** |
| Kibana | **8.15.0** | 与 ES 同版本，可选 |
| Nginx（后续） | 1.27-alpine | 仅后续容器化使用 |
| JDK（后端） | **17** | Spring Boot 3 基线；本机可用 21 编译，产物按 17 |

> 所有镜像都写死版本，不使用 `latest`。升级时一次只动一个组件，先看 release notes 与插件兼容矩阵。

## 4. 网桥与端口

### 4.1 自定义 bridge

`deploy/docker-compose.yml` 中定义：

```yaml
networks:
  glimmer-net:
    name: glimmer-net
    driver: bridge
    ipam:
      config:
        - subnet: 172.28.0.0/16
          gateway: 172.28.0.1
```

| 项 | 值 | 说明 |
|---|---|---|
| 网络名 | `glimmer-net` | 固定名称，避免 Compose 项目前缀变化导致容器解析不到 |
| 驱动 | `bridge` | 单机部署，不需要 overlay |
| 子网 | `172.28.0.0/16` | 与 VM 所在 `192.168.157.0/24` 不冲突 |
| 网关 | `172.28.0.1` | Docker 网桥网关 |
| DNS | Docker 内嵌 DNS | 容器用服务名互访 |

部署前检查子网是否已被占用：

```bash
ip route | grep 172.28 || echo "172.28.0.0/16 可用"
docker network ls
```

如果冲突，改 `subnet` / `gateway` 后重建网络：

```bash
docker compose down
docker network rm glimmer-net 2>/dev/null || true
docker compose up -d
```

> **边界**：core 与 cache 是两个独立 Redis 进程，**禁止跨实例做多 Key 原子操作**；需要原子性的数据必须落在同一个实例（core）。

### 4.2 端口映射

| 宿主机端口 | 容器 | 用途 | 是否对开发机开放 |
|---:|---|---|---|
| 3306 | mysql | MySQL | ✅ |
| 6379 | redis-core | 锁 / Token / 秒杀 | ✅ |
| 6380 | redis-cache | 缓存 / 限流 | ✅ |
| 5672 | rabbitmq | AMQP | ✅ |
| 15672 | rabbitmq | 管理台 | ✅（仅内网） |
| 9200 | elasticsearch | REST | ✅ |
| 5601 | kibana | Kibana | 可选 |
| 8080 | backend（后续） | Spring Boot | 后续 |

所有映射都写成 `${BIND_IP:-192.168.157.129}:<host>:<container>`，**不要绑 `0.0.0.0`**。

### 4.3 firewalld

只放行开发机网段，不按端口对全网开放：

```bash
for p in 3306 6379 6380 5672 15672 9200 5601 8080; do
  sudo firewall-cmd --permanent --add-rich-rule="rule family=ipv4 source address=192.168.157.0/24 port port=${p} protocol=tcp accept"
done
sudo firewall-cmd --reload
sudo firewall-cmd --list-rich-rules
```

## 5. 数据卷

### 5.1 卷清单

| 卷名 | 容器挂载点 | 内容 | 是否持久化 | 备份方式 |
|---|---|---|---|---|
| `mysql-data` | `/var/lib/mysql` | 业务库（权威数据） | ✅ | `mysqldump` + VM 快照 |
| `redis-core-data` | `/data` | AOF（Token / 库存 / 资格 / 布隆） | ✅ | `BGREWRITEAOF` + 拷贝 AOF + VM 快照 |
| `rabbitmq-data` | `/var/lib/rabbitmq` | 队列 / 交换机 / 用户元数据 | ✅ | 以 MySQL 业务数据为准，卷主要保留元数据 |
| `es-data` | `/usr/share/elasticsearch/data` | 搜索索引 | ✅ | 可从 MySQL 全量重建，非权威 |
| `redis-cache` | — | 详情 / Feed / 限流 | ❌ **故意不持久化** | 丢失后回源 DB / 重建，不备份 |

Compose 项目名为 `glimmer`，卷实际路径通常是：

```bash
ls -1 /var/lib/docker/volumes/ | grep glimmer
# glimmer_mysql-data
# glimmer_redis-core-data
# glimmer_rabbitmq-data
# glimmer_es-data
```

### 5.2 备份与恢复

```bash
cd /path/to/glimmer/deploy
set -a; . ./.env; set +a

# MySQL 逻辑备份
docker compose exec -T mysql \
  mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction \
  --routines --triggers glimmer > "glimmer-$(date +%F).sql"

# redis-core 落盘
docker compose exec -T redis-core redis-cli BGREWRITEAOF

# 卷级备份（停机或低峰执行）
docker run --rm -v glimmer_mysql-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/mysql-data-$(date +%F).tgz -C /data .
```

恢复 MySQL：

```bash
gunzip -c glimmer-2026-10-21.sql.gz | \
  docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" glimmer
```

> `docker compose down` 保留卷；`docker compose down -v` **会删除全部数据卷**，只在确认可重建时使用。

### 6.3 RabbitMQ Dockerfile（延迟消息插件）

`deploy/rabbitmq/Dockerfile`：

```dockerfile
ARG RABBITMQ_VERSION=3.13.7
FROM rabbitmq:${RABBITMQ_VERSION}-management

ARG DELAYED_PLUGIN_VERSION=3.13.0

# 延迟消息插件：秒杀 30 分钟关单依赖它。
# 如果 VM 无法访问 GitHub，可手动下载同名 .ez 放到本目录，改用 COPY。
ADD https://github.com/rabbitmq/rabbitmq-delayed-message-exchange/releases/download/v${DELAYED_PLUGIN_VERSION}/rabbitmq_delayed_message_exchange-${DELAYED_PLUGIN_VERSION}.ez /opt/rabbitmq/plugins/

RUN rabbitmq-plugins enable --offline rabbitmq_delayed_message_exchange
```

离线部署时改成：

```dockerfile
COPY rabbitmq_delayed_message_exchange-3.13.0.ez /opt/rabbitmq/plugins/
```

### 6.4 Elasticsearch Dockerfile（IK 分词）

`deploy/elasticsearch/Dockerfile`：

```dockerfile
ARG ES_VERSION=8.15.0
FROM docker.elastic.co/elasticsearch/elasticsearch:${ES_VERSION}

ARG IK_VERSION=8.15.0

# IK 分词插件版本必须与 ES 完全一致。
# 如果 VM 无法访问 GitHub，可手动下载 zip 放到本目录，改用 COPY + elasticsearch-plugin install file:///...
RUN bin/elasticsearch-plugin install --batch \
    https://github.com/infinilabs/analysis-ik/releases/download/v${IK_VERSION}/elasticsearch-analysis-ik-${IK_VERSION}.zip
```

离线安装：

```dockerfile
COPY elasticsearch-analysis-ik-8.15.0.zip /tmp/ik.zip
RUN bin/elasticsearch-plugin install --batch file:///tmp/ik.zip
```

### 6.5 Nginx（后续，不在当前 Compose 中）

**已定稿（2026-10-24）**：生产 / 演示统一走 **Nginx 同源反代**，浏览器只看到 Nginx 一个 Origin；后端不再为生产环境配置 CORS。本地开发优先用 **Vite proxy**（同样同源），`glimmer.cors` 仅保留为「前端直连 8080」时的开发兜底，生产 profile 保持为空。

`deploy/nginx/nginx.conf` 已准备好：前端静态托管（`/` + history 回退）、`/api/` 反代、`/ws/` Upgrade、SSE 关闭 `proxy_buffering`、`X-Trace-Id` 透传。
当前后端跑在 Windows 宿主机，Nginx 若跑在 VM 上需要反向访问 Windows，网络路径不清晰，因此**本阶段不启动**。等后端容器化后，在 Compose 中增加 `nginx` 服务并挂载该配置，见 §14。

### 6.6 后端配置

```yaml

    url: jdbc:mysql://${MYSQL_HOST:192.168.157.129}:${MYSQL_PORT:3306}/${MYSQL_DATABASE:glimmer}?...
    username: ${MYSQL_USER:glimmer}
    password: ${MYSQL_PASSWORD:}
  rabbitmq:
    host: ${RABBITMQ_HOST:192.168.157.129}
    port: ${RABBITMQ_PORT:5672}

glimmer:
  jwt:
    secret: ${JWT_SECRET:}
  storage:
    oss:
      endpoint: ${OSS_ENDPOINT:}
      bucket: ${OSS_BUCKET:}
      access-key-id: ${OSS_ACCESS_KEY_ID:}
      access-key-secret: ${OSS_ACCESS_KEY_SECRET:}
      public-base-url: ${OSS_PUBLIC_BASE_URL:}
  redis:
    core:
      host: ${REDIS_CORE_HOST:192.168.157.129}
      port: ${REDIS_CORE_PORT:6379}
      password: ${REDIS_CORE_PASSWORD:}
    cache:
      host: ${REDIS_CACHE_HOST:192.168.157.129}
      port: ${REDIS_CACHE_PORT:6380}
      password: ${REDIS_CACHE_PASSWORD:}
```

图片存储开发与发布都只使用 OSS，需配置
`OSS_ENDPOINT` / `OSS_BUCKET` / `OSS_ACCESS_KEY_ID` / `OSS_ACCESS_KEY_SECRET`。OSS 桶保持私有，
但需关闭 Bucket 的「阻止公共访问」，后端才能在上传时通过对象 ACL 把单个对象设为 `public-read`；否则上传返回
`50301`。AK/SK 只放在 `.env`，不要提交。

### 6.7 健康检查脚本

`deploy/smoke.sh` 会读取 `.env`，检查：

- 6 个容器是否运行；
- MySQL `mysqladmin ping`；
- redis-core / redis-cache `PING`；
- RabbitMQ diagnostics 与延迟插件；
- ES `_cluster/health`；
- Redis 的 `maxmemory-policy` 是否分别 `noeviction` / `allkeys-lru`。

## 7. 启动顺序

### 7.1 VM 预检与系统参数

完整命令见 [`deploy/README.md`](../deploy/README.md) §2–§5，核心是：

```bash
# CentOS 7 源切 vault（如果 yum 404）
sudo sed -i 's/mirrorlist/#mirrorlist/g; s|#baseurl=http://mirror.centos.org|baseurl=http://vault.centos.org|g' /etc/yum.repos.d/CentOS-*.repo
sudo yum clean all && sudo yum makecache

# Docker 24.0.9 + Compose v2
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# 内核参数
sudo tee /etc/sysctl.d/99-glimmer.conf >/dev/null <<'EOF'
vm.max_map_count=262144
vm.overcommit_memory=1
net.ipv4.ip_forward=1
net.core.somaxconn=1024
fs.file-max=100000
EOF
sudo sysctl --system

# 关闭 THP
echo never | sudo tee /sys/kernel/mm/transparent_hugepage/enabled
```

### 7.2 准备 `.env`

cd /path/to/glimmer/deploy

## 12. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| `docker compose` 报 `unknown field name` | 用了 Compose v1 或旧版 v2，升级到 v2.29.x |
| ES 报 `vm.max_map_count [65530] is too low` | 执行 §7.1 的 sysctl，并确认 `sysctl --system` 生效 |
| Redis 容器反复重启 | `.env` 密码为空、含 `$` 或特殊字符；看 `docker compose logs redis-core` |
| MySQL 连不上 | 端口未放行 / `BIND_IP` 不是 VM 当前 IP / 用户 host 不是 `%` |
| SSH 能通，但 3306/6379/6380 从宿主机超时 | `sysctl net.ipv4.ip_forward` 为 0；Docker 发布端口需要转发。设为 1 并写入 `/etc/sysctl.d/` |
| RabbitMQ 延迟插件缺失 | 构建时 `ADD` 失败；看构建日志，离线改用 `COPY` |
| IK 插件 404 | `IK_VERSION` 与 `ES_VERSION` 不一致，或 GitHub release 不可达 |
| ES 启动 OOM | 8 GB VM 同时开 Kibana；降低 heap 或停 Kibana |
| `172.28.0.0/16` 冲突 | 改 Compose 的 subnet / gateway，重建 `glimmer-net` |
| 后端启动报 `JWT_SECRET 未配置或长度不足` | `.env` 中设置 ≥32 字节的 `JWT_SECRET` |
| 后端连不上 Redis | core 用 6379、cache 用 6380；两个密码不要混用 |
| 磁盘满 | `docker system df` / `df -h`；清理旧镜像、检查 ES 索引 |

## 14. 后续：后端与 Nginx 容器化

当前 Compose **故意不包含 backend / nginx**：骨架阶段还没有可运行的 jar，加入会让 `docker compose up` 构建失败。等 M1 链路稳定后，再按下面方式加入：

```yaml
  backend:
    build: ./backend          # 需要新增 backend/Dockerfile
    container_name: glimmer-backend
    environment:
      MYSQL_HOST: mysql
      REDIS_CORE_HOST: redis-core
      REDIS_CORE_PORT: 6379
      REDIS_CACHE_HOST: redis-cache
      REDIS_CACHE_PORT: 6379
      RABBITMQ_HOST: rabbitmq
      ELASTICSEARCH_URIS: http://elasticsearch:9200
    ports:
      - "${BIND_IP}:8080:8080"
    depends_on:
      mysql:
        condition: service_healthy
      redis-core:
        condition: service_healthy
      redis-cache:
        condition: service_healthy
      rabbitmq:
        condition: service_healthy
    networks:
      - glimmer-net

  nginx:
    image: nginx:1.27-alpine
    container_name: glimmer-nginx
    ports:
      - "${BIND_IP}:80:80"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - backend
    networks:
      - glimmer-net
```

> 图片写入 OSS，后端与 Nginx 都不需要上传卷。容器化后，Redis 两个实例的容器端口都是 6379；后端配置中的 `REDIS_CACHE_PORT` 要改为 `6379`，不能再写宿主机的 6380。

### 14.1 同源反代切换清单

1. **前端开发期**：Vite 配 `server.proxy['/api'] → http://localhost:8080`，前端请求一律用相对路径 `/api/...`；浏览器只看到 5173，不触发 CORS。
2. **后端容器化**：新增 `backend/Dockerfile`，在 Compose 中加入 `backend` 服务；`upstream` 使用服务名 `backend:8080`。
3. **前端产物**：`npm run build` 后把 `dist/` 挂到 Nginx 的 `/usr/share/nginx/html`（或打进镜像）。
4. **Nginx 服务**：加入 Compose，挂载 `deploy/nginx/nginx.conf`；对外只暴露 Nginx 的 80/443，后端 8080 不对外。
5. **前端 baseURL**：从 `http://localhost:8080` 改为同源相对路径 `/api`。
6. **CORS 收口**：生产 profile 的 `glimmer.cors.allowed-origins` 保持为空；只有本地直连 8080 时才使用 `application-dev.yml` 的白名单。
7. **联调验证**：依次验证 `/api/v1/auth/sms-code`、`/api/...` 鉴权、上传接口返回的 OSS URL、`/ws/` 握手、`/api/v1/ai/` SSE 逐条输出，以及 `X-Trace-Id` 在 Nginx 与后端日志中一致。
8. **公网部署**：再加 TLS（80 → 443）、域名、`X-Forwarded-Proto`；如需流量兜底，在 Nginx 配 IP 维度 `limit_req`，不替代应用层用户额度。

> CORS 是浏览器行为，不是鉴权；同源反代只消除跨域限制，JWT + Redis 白名单仍然必须保留。
