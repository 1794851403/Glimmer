   - **限购 N 与幂等键冲突**：消费者幂等键 `{userId}:{activityId}` 与唯一索引 `uk_user_activity` 都等价于"一用户一单"；当 N > 1 时，Lua 会放行第 2 次抢购并扣库存，但消费者会将其当作重复消息丢弃 → **Redis 扣了库存、订单没建**。

## 轮次 3 · 2026-10-18

### 做了什么

1. **§6.7.8 对账方案答疑** —— 明确「`bought` 与订单表差集」无法区分正常在途与真丢失：`bought` 只有计数、没有 requestId 与时间戳，差集天然包含「刚扣减、消息仍在队列/消费中/DB 事务未提交」的请求。
2. **提出对账模型：请求账本 + 时间水位线 + 状态机收敛**
   - 扣减 Lua 内原子登记 `pending` ZSet（score=时间戳）与每请求 Hash（userId/activityId/qty/status）；
   - 对账只处理年龄超过 W1 的记录，W1 = 全链路正常最大耗时（建议 10–15 min，压测校准）；
   - 命中后按证据处理：已有订单只修状态；无订单优先重投（幂等）；重投耗尽才 CAS 释放库存；
   - 关单路径使用独立水位 W2 = 35 min（延迟消息 30 min + 缓冲）、W3 = 5 min（关单后 Redis 回补缓冲）。
3. **修正库存判据** —— 异步系统允许「在途差额」，改用三条恒等式：Redis 内部、DB 内部、跨系统桥接式（差额 = PENDING + 已关闭未回补）。同时指出：DB 扣库存与建单必须同一事务；禁止有并发抢购时用 `SET` 全量重建 Redis 库存。
4. 该账本同时解决 **#2 requestId 缺少结果状态**：PENDING / PROCESSING / ORDERED / FAILED / RELEASED 可直接供结果查询接口读取。

### 产出

- 本轮为方案讲解与评审，`02-架构设计文档.md` 暂未修改（待用户确认）。

### 下一步

1. 用户确认对账方案（推荐 B：Redis 请求账本）与限购 N 方案（requestId 幂等 + `t_seckill_quota` 条件更新）。
2. 修订 `02-架构设计文档.md` §6.7.2–6.7.8 与 §12（新增 W1/W2/W3 参数）后，进入 `03-数据库设计文档.md`。

## 轮次 4 · 2026-10-18

### 做了什么

1. 用户提出「小项目是否过重」，对轮次 3 的方案做复杂度裁剪，区分「正确性必需」与「生产级完备性」。
2. **结论：MVP 不做请求级账本与自动库存回补**，改为「静默期对账 + 安全修复」：
   - **运行期只做只读监控/告警**，不做破坏性自动补偿 → 不会误伤异步在途请求；
   - **活动结束 + 队列排空 + 支付超时窗口后**，以 DB 为准全量重建 Redis（库存 + 限购计数），此时不存在在途，差集才有意义；
   - **唯一自动修复是重投补建订单**（幂等，重复消息由唯一索引吸收）；库存回补永远不自动执行；
   - 超时关单用定时扫描兜底（35 分钟），延迟消息可保留为演示/优化，不作为正确性前提；
   - 限购 N 建议收敛为「一用户一张订单、数量 ≤ N」，避免多单幂等与 quota 表。
3. 完整方案（请求账本 + W1/W2/W3 + 状态 CAS）保留为 §6.7.8 的「演进方向」，不作为 MVP 实现。

### 产出

- 复杂度分级建议：A 最小（静默期对账，推荐）/ B 折中（轻量时间戳 + 运行期重投）/ C 完整（请求账本）。

   - **结论：不需要两个前端工程**，推荐单 SPA + `/admin/**` 角色路由 + 独立 AdminLayout，管理页按需懒加载；

## 轮次 13 · 2026-10-19

### 做了什么

1. **MySQL 版本选型答疑**：确认继续使用 MySQL 8.0，不降级到 5.7。
   - 5.7 已于 2023-10 EOL；8.0 默认 utf8mb4、CHECK 约束生效、支持 CTE/窗口函数，且与 Spring Boot 3 + `mysql-connector-j` 8.x 匹配；
   - 本项目的 11 张表在 5.7 上也能跑（生成列、ngram 全文索引 5.7.6+ 支持），因此不是「非 8 不可」，而是没有理由选已停止维护的版本。
2. **认证方式差异**：8.0 默认 `caching_sha2_password`（SHA-256），5.7 默认 `mysql_native_password`（SHA-1）；旧驱动/旧 Navicat 可能报 `Public Key Retrieval is not allowed` 或 `Authentication plugin ... cannot be loaded`。
   - 本地 JDBC 加 `allowPublicKeyRetrieval=true&sslMode=DISABLED`，生产启用 TLS；
   - 驱动用 `com.mysql:mysql-connector-j` 8.x；`mysql_native_password` 在 8.0.34 起废弃、8.4 默认禁用、9.0 移除，不作为正式方案。
