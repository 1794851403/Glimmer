## 1. 通用约定

### 1.1 Base URL 与版本

| 项 | 约定 |
|---|---|
| 业务 API 前缀 | `/api/v1` |
| 完整示例 | `https://api.glimmer.example/api/v1/posts` |
| 本地开发 | 后端在宿主机：`http://localhost:8080/api/v1`；后端在 VM：`http://192.168.157.129:8080/api/v1` |
| WebSocket | `/ws/danmaku`（不放在 `/api/v1` 下） |
| 版本策略 | 路径版本；破坏性变更升 `/api/v2`，旧版本保留一个迭代 |

### 1.2 请求与响应格式

- 除文件上传与 SSE 外，请求与响应均为 `application/json; charset=utf-8`。
- 文件上传使用 `multipart/form-data`。
- AI 流式接口响应为 `text/event-stream; charset=utf-8`。
- 服务端不依赖 Cookie；登录态统一放在 `Authorization` 头。
- 所有接口默认支持 gzip；客户端应发送 `Accept-Encoding: gzip`。

### 1.3 认证与鉴权

#### 1.3.1 Token

| Token | 形态 | 有效期 | 存储 |
|---|---|---|---|
| Access Token | JWT（HS256） | 7 天 | 客户端内存 / sessionStorage |

请求头：

```http
Authorization: Bearer <accessToken>
```

- JWT 载荷只放 `userId`、`role`、`iat`、`exp`，与 02 §6.10.1 一致；不放手机号等敏感信息。
- Redis 保存 `glimmer:user:token:{userId} = token`（TTL 7 天），与 02 §6.10.1 一致；登出、封禁时删除，实现**主动失效**。
- 单用户单 Token：同一账号再次登录会覆盖 Redis 中的 Token，旧 Token 立即失效（MVP 不做多端并存）。
- 非白名单接口：JWT 缺失 / 签名无效 / Redis 不匹配返回 `40101`，JWT 过期返回 `40102`；白名单接口遇到这些情况按游客处理。客户端收到 `40101` / `40102` 都清除本地 Token 并重新登录，MVP 不提供 Refresh Token。
- 被封禁用户（`t_user.status=1`）：封禁时删除 Redis Token，已签发 Token 的后续请求因查不到 / 不匹配返回 `40101`；用户重新登录时，登录接口校验 `status=1` 并返回 `40302`（账号已被封禁）。不在每个请求上额外查询用户状态。

#### 1.3.2 角色与鉴权规则

| 角色 | 值 | 说明 |
|---|---|---|
| 游客 | 无 Token | 只能访问 1.3.3 白名单内的接口 |
| 注册用户 | `USER` | 默认角色 |
| 管理员 | `ADMIN` | `/api/v1/admin/**` 全部要求 `ADMIN` |

- **默认拒绝**：`/api/v1/**` 全部要求登录；只有 1.3.3 白名单按「方法 + 路径」精确放行。Controller 不写 `@RequireLogin` / `@RequireRole` 之类注解，鉴权集中在拦截器。
- 白名单接口仍会尝试解析 Token：有合法 Token 时注入 `UserContext`，补充 `liked` / `collected` / `isFollowing` 等个性化字段；无 Token 或 Token 过期 / 非法时按匿名处理，不返回 401。
- 非白名单接口缺少 Token / Token 非法返回 `40101`，Token 过期返回 `40102`。
- `/api/v1/admin/**` 在登录校验通过后统一校验 `role=ADMIN`，不依赖前端隐藏菜单。
- 资源归属（作者本人 / 订单所有者）在 Service 层按 JWT 中的 `userId` 校验，属于业务鉴权，不是接口级登录控制。
- CORS 预检 `OPTIONS` 直接放行。
- WebSocket `/ws/danmaku` 握手由独立 `HandshakeInterceptor` 校验 JWT，仍要求登录。
- 下文各接口的「鉴权」字段只是文档说明，实现上统一由上述规则推导，不在每个接口上单独加注解。

### 1.4 ID、时间、金额与文本

| 类型 | JSON 表示 | 说明 |
|---|---|---|
| BIGINT ID | **字符串** | 避免 JS `Number` 超过 2^53 精度丢失；如 `"1001"` |
| 时间 | **epoch 毫秒整数** | 与 ES `epoch_millis`、弹幕 `ts` 一致；如 `1730000000000` |
| 金额 | **字符串十进制** | 如 `"99.00"`，避免浮点误差；服务端用 `BigDecimal` |
| 文本 | 纯文本 | 不接受 HTML；换行用 `\n`；服务端保留原文、不拼 HTML，前端用 `textContent` 渲染 |
| 布尔 | `true` / `false` | 不使用 0/1 |
| 枚举 | 数字或大写字符串 | 与表字段一致的数字枚举直接返回数字；派生状态用字符串 |

- 请求路径中的 ID 同时接受数字与字符串，服务端按 `Long` 解析。
- 可选字段默认省略（Jackson `NON_NULL`）；本文示例为说明语义会显式写出 `null`。客户端应同时处理“字段缺失”与 `null`，两者都按无值处理。
- 所有时间由服务端生成，客户端不得传入 `createdAt` / `publishedAt` 等服务端字段。

### 1.5 统一响应结构

除 `204 No Content` 与 SSE 外，所有响应使用统一信封：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "4f7c2a9e8b1d4c6f"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 0 表示成功；非 0 见 §1.8 |
| `message` | string | 面向调用方的简要说明；可直接展示的文案用中文 |
| `data` | object / array / null | 业务数据；错误时为 `null` |
| `traceId` | string | 服务端链路 ID；同时写入响应头 `X-Trace-Id` |

HTTP 状态码与 `code` 同时表达语义：

- HTTP 2xx：请求已被正确处理（业务成功或幂等成功）；
- HTTP 4xx：参数、鉴权、权限、状态冲突、限流；
- HTTP 5xx：服务端或依赖异常；
- 客户端应**同时判断 HTTP 状态与 `code`**，不要只看其中一个。

### 1.6 分页

#### 1.6.1 游标分页（Feed / 搜索 / 评论 / 收藏）

请求参数：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `cursor` | string | 无 | 上一页返回的 `nextCursor`；首页不传 |
| `size` | int | 20 | 1~50 |

响应（`CursorPage<T>`）：

```json
{
  "items": [],
  "nextCursor": "eyJwdWJsaXNoZWRBdCI6MTczMDAwMDAwMDAwMCwiaWQiOiIxMDAxIn0",
  "hasMore": true
}
```

- `cursor` 对客户端**不透明**，不要解析或拼接。
- MVP 口径：坏游标（无法解析、字段缺失、ID 非法）不返回参数错误，按首页处理；`size` 非正数按 1、超过 50 按 50 夹取，不报错。
- 游标内部包含排序键与 ID，保证深分页稳定；排序键示例：
  - 最新：`publishedAt, id`；
  - 热榜：`score, publishedAt, id`；
  - 搜索：`_score, publishedAt, id`；
  - 评论：`createdAt, id`。
- `hasMore=false` 时 `nextCursor` 为 `null`。

#### 1.6.2 页码分页（管理端列表）

请求参数：`page`（从 1 开始，默认 1）、`size`（默认 20，最大 100）。

响应（`PageResult<T>`）：

```json
{
  "items": [],
  "page": 1,
  "size": 20,
  "total": 123,
  "totalPages": 7
}
```

> 管理端数据量可控，使用页码分页便于运营跳页；用户端一律游标分页，避免深分页漂移。

### 1.7 幂等与并发

| 场景 | 幂等键 | 重复请求的行为 |
|---|---|---|
| 点赞 / 取消点赞 | `(userId, postId)` 唯一键 | 返回当前状态与计数，HTTP 200 |
| 收藏 / 取消收藏 | `(userId, postId)` 唯一键 | 同上 |
| 关注 / 取关 | `(followerId, followeeId)` 唯一键 | 同上 |
| 发帖 | 无客户端幂等键；客户端提交后禁用按钮 | 重复提交会产生多条帖子，MVP 不提供去重 |
| 抢购 | `(userId, activityId)` 唯一键 + Redis `bought` | 返回当前抢购状态，不重复扣库存 |
| 支付（模拟） | `orderNo + 状态 CAS` | 已支付返回当前订单，不重复扣款 |
| 审核 / 下架 / 恢复 | `status` CAS + 操作人校验 | 已是目标状态返回当前详情；非法流转返回 `40901` / `40904` |

- 并发更新统一使用 `UPDATE ... WHERE id=? AND status=?` 的 CAS；受影响行数为 0 时返回 `40903` 或 `40904`。
- 客户端对 `5xx`、`429` 可指数退避重试；对 `4xx` 不做自动重试；`401` 清除本地登录态并跳转登录。

### 1.9 限流

| 场景 | 维度 | 阈值 | 超限响应 |
|---|---|---|---|
| 验证码 | 手机号 | 5 次/小时 | `42901` + `Retry-After` |
| 登录 | 手机号 | 10 次/小时 | `42901` |
| 抢购 | 用户 | 10 次/小时；活动总量由库存 / 限购控制 | `42901` |
| AI 提问 | 用户 | 20 次/小时；同时 1 条流 | `42901` / `44003` |

> 限流只按手机号 / 用户的小时额度计算，**不做 IP 维度，也不做全站 IP QPS 兜底**。验证码前端可保留 60 秒重发倒计时，但服务端只校验 5 次/小时。公网部署如需流量兜底，在 Nginx 层配置 `limit_req` / `limit_conn`，不进入业务代码。
>
> 只对以上关键链路限流。发帖、评论、点赞、收藏、关注、上传、搜索、支付、弹幕等不单独限流，依赖登录校验、唯一约束、幂等、长度限制与容量控制；阈值走配置，正常用户不会触发。

响应头（命中上述限流时）：

```http
Retry-After: 30
X-RateLimit-Limit: 10
X-RateLimit-Remaining: 0
```

### 1.10 可见性与权限矩阵

| 资源 / 操作 | 游客 | 作者本人 | 其他用户 | 管理员 |
|---|---|---|---|---|
| 公开可见帖子详情（`status=0/1`） | ✅ | ✅ | ✅ | ✅ |
| 审核拒绝 / 已下架帖子详情（`status=2/3`） | ❌ | ✅（我的帖子 / 自己的详情） | ❌ | ✅（管理端） |
| 已删除帖子 | ❌ | ❌ | ❌ | ❌（管理端也不可见） |
| 编辑帖子 | ❌ | 可编辑 `status=0/1/2` 的帖子；编辑后统一回到 `0` 待审核并重新入审；`status=3` 已下架不可编辑 | ❌ | 与自己作为作者的规则相同（不能编辑他人帖子） |
| 删除帖子 | ❌ | ✅（终态） | ❌ | 走管理端下架，不代替作者删除 |
| 审核 / 下架 / 恢复 | ❌ | ❌（不能操作自己的帖） | ❌ | ✅（非自己发布的帖） |
| 评论 | ❌ | ✅ | ✅ | ✅ |
| 删除评论 | ❌ | 自己的评论 / 自己帖子下的评论 | 自己的评论 | ✅ |

- 公开详情对审核拒绝 / 已下架 / 已删除帖子统一返回 `40402`，不泄露具体原因；作者通过“我的帖子”查看。
- 待审核帖子已公开，其他用户可直接访问详情；审核拒绝后立即变为不可见。
- 作者可编辑待审核 / 已发布 / 审核拒绝的帖子；编辑后状态统一回到 `0` 待审核，内容立即生效并重新入审；编辑不重置 `published_at`。
- 已下架帖子不可编辑；作者只能等待管理员恢复或删除。

## 3. 认证与用户

### 3.1 发送验证码

`POST /api/v1/auth/sms-code`

- 鉴权：匿名
- 限流：同一手机号 5 次/小时；前端可保留 60 秒重发倒计时

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `phone` | string | 是 | 中国大陆手机号，11 位 |
| `scene` | string | 否 | `LOGIN`（默认）；MVP 注册与登录合一，无需 `REGISTER` |

```json
{
  "phone": "13800138000",
  "scene": "LOGIN"
}
```

响应 `200`：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "expireIn": 300,
    "resendAfter": 60
  },
  "traceId": "4f7c2a9e8b1d4c6f"
}
```

说明：

- MVP 使用 Mock 短信：验证码写入 Redis（`glimmer:auth:sms:{phone}`，TTL 5 分钟），并在服务端日志打印。
- `local` / `dev` profile 额外返回 `debugCode` 字段，**生产环境绝不返回**。
- 同一手机号 60 秒内重复请求返回 `42901`。

错误：`40002`、`42901`。

### 3.2 登录 / 自动注册

`POST /api/v1/auth/login`

- 鉴权：匿名
- 限流：同一手机号 10 次/小时

请求体：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `phone` | string | 是 | 手机号 |
| `code` | string | 是 | 6 位数字验证码 |

```json
{
  "phone": "13800138000",
  "code": "123456"
```

## 4. 图片上传

### 4.1 上传图片

`POST /api/v1/files/images`

- 鉴权：登录
- Content-Type：`multipart/form-data`

表单字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | file | 是 | jpg / png / webp，≤5MB |

响应 `200`：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "url": "https://your-bucket.oss-cn-beijing.aliyuncs.com/images/1001/2026/10/29/8f3c.jpg",
    "size": 348212,
    "contentType": "image/jpeg"
  },
  "traceId": "4f7c2a9e8b1d4c6f"
}
```

说明：

- **MVP 为后端中转上传**：前端 `multipart/form-data` 提交到后端，后端读取字节后写入存储；不向浏览器下发 OSS 密钥。
- **最小校验**：只校验扩展名（jpg / jpeg / png / webp）与大小（≤5MB），不校验 MIME、magic bytes，也不做图片内容审核；空文件按类型不支持处理。
- 对象名由服务端生成：`images/{userId}/{yyyy}/{MM}/{dd}/{uuid}.{ext}`，不包含原始文件名或用户输入。
- 开发与发布都写入同一个 OSS 桶，不提供本地存储实现。
- OSS 桶保持私有，上传时仅对本次对象设置 `PublicRead`（随 PutObject 提交 `x-oss-object-acl`），返回可公网访问的 URL；Bucket 需关闭「阻止公共访问」，否则对象级 ACL 会被拒绝并返回 `50301`。
- 直传 OSS（预签名 URL）、magic bytes 校验与图片内容审核列为演进。

错误：`45001`、`45002`、`50301`（未登录仍按通用规则返回 `40101`）。

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": "1001",
    "status": 0,
    "statusText": "已发布待审核",
    "publishedAt": 1730000000000,
    "message": "发布成功，内容已公开，审核结果将另行通知"
```

行为：

1. 事务插入 `t_post`、`t_post_image`、`t_post_tag`；

### 5.2 帖子列表（最新 / 热度）

`GET /api/v1/posts?sort=latest&cursor=&size=20`

- 只返回公开可见帖子

说明：

- `latest` 按 `publishedAt DESC, id DESC`；
- `hot` 复用热榜逻辑，见 §5.9；
- 有登录态时补充 `liked` / `collected`。

MVP 实现：

- 当前只支持 `latest`（不传 / 空 / `latest` 等价）；`hot` 与其他未知值返回 `40001`，避免前端误以为热榜已生效；

错误：`40001`。

### 5.3 帖子详情

`GET /api/v1/posts/{postId}`

- 鉴权：可选登录
- 路径参数：`postId`

响应 `200`：`PostDetail`。

可见性：

| 访问者 | 条件 | 结果 |
|---|---|---|
| 游客 / 其他用户 | 公开可见（`status IN (0,1) AND is_deleted=0`） | 正常返回 |
| 作者本人 | 未删除（0/1/2/3） | 正常返回，带审核原因与操作标记 |
| 管理员 | 未删除 | 正常返回；管理端另有详情接口 |
| 任何人 | `is_deleted=1` | `40402` |

说明：

- 待审核（`status=0`）帖子已公开，游客和其他用户可正常访问。
- 公开详情先查 Redis 详情缓存；作者 / 管理员查看自己的审核拒绝 / 已下架帖绕过公共缓存。
- 浏览数在 Redis 异步累加，接口不等待落库；返回的是当前缓存 / DB 值，允许短暂滞后。
- 公开详情不返回 `auditReason` 与 `aiTagStatus`。

MVP 实现：

- 直接查 MySQL（帖子、图片、标签、作者、关注关系），不接 Redis 详情缓存；浏览数暂不异步累加，返回 DB 计数。
- `liked` / `collected` 在互动模块接入前固定为 `false`；登录用户查看他人帖子时，`isFollowingAuthor` 实时查询 `t_user_follow`。
- `postId` 非法（空、非数字、≤0）与帖子不存在 / 不可见统一返回 `40402`，不额外区分，避免探测。
- `canEdit` 仅作者且 `status IN (0,1,2)` 时为 `true`；`canResubmit` 仅作者且 `status=2`；`canDelete` 仅作者。已删除帖子任何人不可见。

错误：`40402`。

### 5.4 编辑帖子

`PUT /api/v1/posts/{postId}`

- 鉴权：登录
- 语义：**全量替换**可编辑字段

请求体：同 §5.1。

响应 `200`：`PostDetail`。

允许编辑的状态：

编辑后状态统一回到 `0` 已发布待审核：

| 操作人 | 帖子状态 | 结果 |
|---|---|---|
| 作者 | `0` 已发布待审核 | 更新内容，状态仍为 0，重新进入审核队列 |
| 作者 | `1` 已发布 | 更新内容，状态变为 0，立即重新公开并重新进入审核 |
| 作者 | `2` 审核拒绝 | 更新内容，状态变为 0，立即重新公开并重新进入审核 |
| 作者 | `3` 已下架 | `40901`（需管理员恢复或删除） |
| 其他人 | 任意 | `40301` |

说明：

- 只有作者本人可编辑；管理员编辑自己的帖子也遵循同一规则，不能编辑他人帖子。
- **编辑即重新提交**：状态回到 0，清空 `audit_reason` / `audited_at` / `audited_by`，重新进入待审队列。
- 编辑会替换 `t_post_image` 与 `t_post_tag`（先删后插），同一事务完成。
- 不重置 `published_at`、`last_interaction_at`；不重复 Feed 写扩散；原状态 1/2 的帖子编辑后立即重新公开。
- **MVP 实现**：直接更新 MySQL，图片与标签先删后插；详情缓存、`SEARCH_UPSERT`、AI 打标 MQ 与 Feed 写扩散随对应模块接入。
- 审核期间编辑：以最新内容为准，管理端审核前应刷新详情；编辑会重新入审，审核队列按 `postId` 去重。

错误：`40001`、`40004`、`40301`、`40402`、`40901`。

### 5.7 关注流

`GET /api/v1/feed/follow?cursor=&size=20`

- 鉴权：登录
- 返回当前用户关注的作者（不含自己）的公开可见帖子
- 排序：`publishedAt DESC, id DESC`

响应 `200`：`CursorPage<PostSummary>`。

说明：

- 目标形态为推拉结合：普通作者写扩散到粉丝收件箱；大 V 走拉模式，读时归并。
- **第一轮实现（v1.21）为「收件箱优先 + MySQL 兜底」**：
  - 发帖事务提交后发布本地事件，经 RabbitMQ 异步写入粉丝收件箱 `glimmer:feed:inbox:{userId}`；发帖接口不等待写扩散；
  - 关注成功后回填被关注者最近 50 条公开帖子，保证关注后立刻有内容；
  - 读取时先查收件箱并按游标过滤；只有收件箱能凑满一页 + 1 条可见帖子才直接返回，否则用同一游标回源 MySQL，避免收件箱裁剪导致分页提前结束；
  - 收件箱最多 200 条、TTL 30 天；首页距上次读取超过 24 小时或收件箱为空时，先按关注列表回源最近 50 条重建；
  - 取关不清理收件箱，读取时按当前关注集合过滤；审核拒绝 / 下架 / 删除的帖子在读取时按公开可见条件过滤；
  - Redis 不可用或收件箱数据不足时回源 MySQL，接口仍返回 200。
- 未关注任何人时返回空页（`items=[]`、`hasMore=false`、`nextCursor=null`），不回退到全站最新。
- 读时统一过滤 `status IN (0,1) AND is_deleted=0`；排序 `publishedAt DESC, id DESC`，游标编码 `publishedAt + id`。
- 坏游标按首页处理；`size` 默认 20，越界夹到 1~50。
- 写扩散为 best-effort：MQ 积压、消费者失败或活跃用户集合丢失时可能漏推，但不会回滚发帖 / 关注，也不保证接口结果 100% 完整；漏推内容仍可从作者主页与全站最新获得。大 V 阈值、拉模式归并与热榜 / 推荐流兜底在 Feed 第二轮接入。

错误：`40101`（未登录 / Token 失效）。

### 5.8 推荐流（P1）

`GET /api/v1/feed/recommended?cursor=&size=20`

- 鉴权：可选登录
- 有登录态：按兴趣标签 + 热度 + 时间衰减混合排序；
- 匿名：退化为热榜。

响应 `200`：`CursorPage<PostSummary>`。

说明：

- MVP 为规则推荐（标签 / 热度），不引入向量检索；
- 推荐结果同样过滤公开可见条件。

### 5.9 热榜

`GET /api/v1/feed/hot?cursor=&size=20`

- 鉴权：匿名
- 数据源：Redis ZSet `glimmer:feed:hot`（Top 1000）
- 热度分（与 02 §6.6.1 一致）：`raw = 1×点赞数 + 2×评论数 + 0.1×浏览数`，`score = raw / (ageHours + 2)^1.5`；`ageHours` 基于 `published_at`

响应 `200`：`CursorPage<PostSummary>`。

说明：

- 返回前按 `status IN (0,1) AND is_deleted=0` 过滤；被过滤的条目跳过，不影响后续分页；
- ZSet 为空或 Redis 不可用时，降级为 MySQL 最新公开帖子，响应头 `X-Degraded: hot-fallback`；
- 热榜是 P1，降级不影响主链路。

## 7. 弹幕 WebSocket

### 7.1 连接

```
ws://localhost:8080/ws/danmaku?roomId=post:123&token=<accessToken>
```

生产使用 `wss://`。

| 参数 | 必填 | 说明 |
|---|---|---|
| `roomId` | 是 | `post:{postId}` 或 `activity:{activityId}`（与 02 §6.8 一致） |
| `token` | 是 | Access Token；握手阶段校验 |

鉴权：

- `HandshakeInterceptor` 校验 JWT + Redis Token 白名单；
- 校验失败返回 HTTP 401，连接关闭；
- 校验通过后把 `userId`、`nickname` 写入 session attributes；
- 连接建立后不再逐帧校验 Token；Token 过期可主动关闭（MVP 可接受连接期间不校验）。

房间校验：

| roomId | 校验 |
|---|---|
| `post:{postId}` | 帖子存在且公开可见（`status IN (0,1) AND is_deleted=0`） |
| `activity:{activityId}` | 活动存在且 `status=1`（未发布 / 已下架不可进入） |

连接限制：

- 单用户 ≤3 条连接；
- 单房间连接上限（默认 5,000）；
- 超限关闭并返回错误帧。

### 7.2 客户端帧

发送弹幕：

```json
{
  "type": "SEND",
  "clientMsgId": "c-8f3c9a2e",
  "content": "这个营地我也去过！"
}
```

心跳：

```json
{ "type": "PING", "ts": 1730000000000 }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `type` | string | 是 | `SEND` / `PING` |
| `clientMsgId` | string | 否 | 客户端消息追踪 ID，≤64 字符；用于日志排查 / 重试去重，服务端不强制使用 |
| `content` | string | SEND 必填 | 1~50 个 Unicode code point |

> **发送者不提前本地渲染**：客户端发送 `SEND` 后不插入临时消息，等待服务端广播 `DANMAKU` 后再统一显示。这样所有客户端（包括发送者）看到的顺序、内容、`messageId` 完全一致，因此 MVP **不引入 ACK 帧**。

### 7.3 服务端帧

历史回放（连接成功后立即推送最近 50 条，时间正序）：

```json
{
  "type": "HISTORY",
  "items": [
    {
      "type": "DANMAKU",
      "messageId": "m-1",
      "roomId": "post:123",
      "userId": "2",
      "nickname": "阿野",
      "content": "这个营地我也去过！",
      "ts": 1730000000000
    }
  ]
}
```

实时广播：

```json
{
  "type": "DANMAKU",
  "messageId": "m-2",
  "roomId": "post:123",
  "userId": "3",
  "nickname": "小满",
  "content": "好美",
  "ts": 1730000001000
}
```

心跳响应：

```json
{ "type": "PONG", "ts": 1730000001000 }
```

错误帧：

```json
{
  "type": "ERROR",
  "code": "CONTENT_TOO_LONG",
  "message": "弹幕内容不能超过 50 个字符"
}
```

错误码：

| code | 说明 |
|---|---|
| `CONTENT_TOO_LONG` | 超过 50 个 code point |
| `CONTENT_EMPTY` | 内容为空 |
| `ROOM_NOT_FOUND` | 房间不存在或不可见 |
| `CONNECTION_LIMIT` | 超出单用户 / 单房间连接上限 |
| `UNSUPPORTED_TYPE` | 客户端帧的 `type` 缺失或不是 `SEND` / `PING` |
| `INTERNAL_ERROR` | 服务端异常 |

> 收到未知 `type` 时返回 `UNSUPPORTED_TYPE`，**连接保持**，不静默丢弃；连续大量非法帧可按滥用处理并关闭连接。

### 7.4 处理与边界

- 内容做 HTML 转义 / 去标签，防 XSS；
- 未知客户端 `type` 返回 `UNSUPPORTED_TYPE`；连续非法帧可关闭连接；
- 历史写 Redis List `glimmer:ws:history:{roomId}`，`LPUSH + LTRIM 0 199 + EXPIRE 24h`；
- Redis 写失败只记日志，继续广播（历史降级）；
- 单条 session 发送失败：关闭并移除该 session，不影响其他连接；
- 慢客户端通过 `ConcurrentWebSocketSessionDecorator` 限制发送时间与缓冲，超限关闭；
- MVP 单机广播；多实例演进用 Redis Pub/Sub，协议不变。

## 8. AI 助手（SSE）

> **实施状态（2026-11-04）**：AI 模块首批只实现本节流式对话；F-23 自动打标与 F-24 评论情感分析后置，不参与内容审核。等主线接口收尾后单独开轮实现。

### 8.1 创建会话

`POST /api/v1/ai/chat/session`

- 鉴权：登录

请求体：

```json
{ "postId": "1001" }
```

响应 `200`：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "sessionId": "s-7f3c9a2e",
    "postId": "1001",
    "expiresIn": 1800
  },
  "traceId": "4f7c2a9e8b1d4c6f"
}
```

说明：

- 会话上下文存 Redis，**不落库**；TTL 30 分钟，每次提问续期；
- 会话绑定 `userId + postId`，只有本人可访问；
- 帖子必须对当前用户可见（公开帖或自己的帖子）；
- 最多保留最近 10 轮（20 条消息），超出截断最早消息。

错误：`40402`。

### 8.2 提问并流式接收

`POST /api/v1/ai/chat/stream`

- 鉴权：登录
- 请求头：`Accept: text/event-stream`
- 限流：20 次/小时；同时只允许 1 条进行中的流

请求体：

```json
{
  "sessionId": "s-7f3c9a2e",
  "question": "这个营地适合新手吗？"
}
```

响应头：

```http
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
Connection: keep-alive
X-Accel-Buffering: no
```

事件流示例：

```text
event: start
data: {"sessionId":"s-7f3c9a2e"}

data: {"delta":"这个"}

data: {"delta":"营地"}

data: {"delta":"整体比较平缓，"}

data: {"delta":"适合新手。"}

event: done
data: {"finishReason":"stop","elapsedMs":3200}
```

事件定义：

| event | data | 说明 |
|---|---|---|
| `start` | `{"sessionId":"..."}` | 流建立 |
| 默认 message | `{"delta":"..."}` | 逐 token 内容片段 |
| `done` | `{"finishReason":"stop","elapsedMs":3200}` | 正常结束 |
| `error` | `{"code":44001,"message":"..."}` | 流中异常 |

说明：

- **不要使用浏览器原生 `EventSource`**：它只支持 GET 且会自动重连，生成式场景下重连 = 重复生成 + 重复计费。使用 `fetch` + `ReadableStream` 手动消费 SSE 帧。
- 客户端点击“停止”：`AbortController.abort()` 关闭 HTTP 连接；服务端检测到断开后取消上游 DeepSeek 调用，释放线程与配额。
- 同一用户已有进行中的流时，新请求返回 `44003`。
- 问题长度 1~500 字符；超长返回 `44004`。
- 模型服务不可用：已建立流时发送 `event: error`，未建立流时返回 HTTP 503 + `44001`；**不做规则假回复**。
- 服务端不自动重试；客户端展示“重试”按钮，由用户主动发起新请求。
- 服务端每 15 秒发送一行 SSE 注释（`: ping`）保活，防止网关空闲超时。

错误（流建立前）：`40402`、`42901`、`44002`、`44003`、`44004`、`44001`。

### 8.3 关闭会话

`DELETE /api/v1/ai/chat/sessions/{sessionId}`

- 鉴权：登录；仅会话所有者

响应 `204 No Content`。

说明：删除 Redis 上下文；不影响已经完成的回答。用户直接关闭页面时，上下文由 TTL 自然过期。

错误：`40401`、`44002`。

## 9. 秒杀

### 9.1 活动状态

| 字段 | 值 | 说明 |
|---|---|---|
| `phase` | `UPCOMING` | 已发布，未到开始时间 |
| `phase` | `ONGOING` | 进行中 |

### 9.4 发起抢购

`POST /api/v1/seckill/activities/{activityId}/orders`

- 鉴权：登录
- 限流：同一用户 10 次/小时；活动总量由库存 / 限购控制
- 请求体：无

响应 `202 Accepted`（首次抢购，已入队）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "activityId": "3001",
    "status": "QUEUED",
    "pollAfterMs": 500
  },
  "traceId": "4f7c2a9e8b1d4c6f"
}
```

行为：

1. 校验活动（Redis core）：存在、已发布、在时间窗口内、**不处于 `recovering` 状态**；
2. 执行 Lua：库存判断 + 一人一单资格判断 + 扣减 + 资格标记；
3. 把发送任务提交到秒杀专用有界舱壁线程池，异步发送 MQ（publisher confirm），**不等待 confirm**，立即返回 `202`；
4. 客户端按 `pollAfterMs` 轮询 §9.5，直到 `CREATED` / `CLOSED` / `NOT_PARTICIPATED`；
5. **幂等**：同一用户对同一活动已有资格或订单时，重复 POST 返回 `200` + 当前状态（`QUEUED` / `CREATED` / `CLOSED`），不重复扣库存；不依赖客户端请求 ID；
6. **一人一单**：同一用户对同一活动只能创建一个订单；订单超时关闭后仍占用资格，不能再次抢购；
7. **发送失败补偿**：舱壁拒绝 → 立即回滚资格并返回 `50301`；confirm 失败 / 超时 → 延迟查订单，确认未建单后先写 cancel 标记再回滚资格，客户端轮询会看到 `NOT_PARTICIPATED`，可重新抢购（库存允许时）；
8. **消息晚到保护**：消费者执行前检查 cancel 标记；即使 MQ 消息晚到，也不会在为该用户回滚资格后创建订单。

> `202` 只表示“**已获得资格，服务端正在投递**”，不保证订单已创建。客户端不要因为收到 `202` 就展示“抢购成功”，必须轮询 §9.5。

错误：

| code | 场景 |
|---|---|
| `43001` | 未开始 |
| `43002` | 已结束 |
| `43003` | 售罄 |
| `43004` | 超出每人限购（预留给限购数 > 1；N=1 的重复抢购返回 `200` 当前状态） |
| `43005` | 活动已下架 |
| `42901` | 触发限流 |
| `50301` | Redis / MQ 不可用 |

### 9.5 查询我的抢购结果

`GET /api/v1/seckill/activities/{activityId}/my-order`

- 鉴权：登录；只查询当前登录用户在指定活动下的抢购结果
- 幂等：结果按 `(userId, activityId)` 业务键查询，不依赖客户端请求 ID

响应 `200`：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "activityId": "3001",
    "status": "CREATED",
    "order": {
      "orderNo": "SK202610191234560001",
      "activityId": "3001",
      "quantity": 1,
      "amount": "99.00",
      "status": 0,
      "statusText": "待支付",
      "createdAt": 1730000002000,
      "paidAt": null,
      "closedAt": null
    }
  },
  "traceId": "4f7c2a9e8b1d4c6f"
}
```

`status` 取值：

| 值 | 说明 |
|---|---|
| `NOT_PARTICIPATED` | 无资格、无订单，可以发起抢购 |
| `QUEUED` | 已获得资格，MQ 投递 / confirm 中或消费者尚未建单；`order` 为 null。confirm 失败并回滚后会变成 `NOT_PARTICIPATED` |
| `CREATED` | 订单已创建且未关闭，`order` 有值（`order.status` 0=待支付、1=已支付） |
| `CLOSED` | 订单已超时关闭，`order` 有值；该用户不能再次抢购 |

说明：

- 查询顺序：先按 `(userId, activityId)` 查 `t_seckill_order`，有订单按订单状态返回 `CREATED` / `CLOSED`；无订单再查 Redis `bought`，有标记返回 `QUEUED`，否则返回 `NOT_PARTICIPATED`；
- 轮询建议：500ms 起，指数退避至 2s，最多 15 秒；超时后提示“结果确认中”，可继续查询；
- 即使 POST 响应丢失，也可直接调用本接口恢复状态；
- `QUEUED` 超过 15 秒仍未变为 `CREATED`：服务端由 confirm 失败补偿 / 消费者失败回滚 / 定时对账收敛；失败后回到 `NOT_PARTICIPATED`，可重新抢购；
- `QUEUED` 期间不返回订单号。

错误：`40401`（活动不存在）。

## 11. 状态机与客户端协作

### 11.1 帖子状态与客户端行为

```
普通用户发帖 → 0 已发布·待审核 ──通过──→ 1 已发布 ──下架──→ 3 已下架
                    │                       ↑                    │
                    ├──拒绝──→ 2 审核拒绝  └────── 恢复 ────────┘
                    └──下架──────────────────────────────────────→ 3 已下架

作者编辑 0/1/2 任一状态 → 状态回到 0 已发布·待审核（重新入审；1/2 编辑后立即重新公开）
管理员发帖 → 1 已发布（跳过审核）
```

| 当前状态 | 作者可见操作 | 客户端提示 |
|---|---|---|
| 0 已发布待审核 | 编辑、删除 | “内容已公开，审核中；修改后将重新进入审核” |
| 1 已发布 | 编辑、删除 | 正常展示；编辑后提示“修改后需重新审核” |
| 2 审核拒绝 | 编辑、直接重新提交、删除 | 展示拒绝原因 + “修改后重新提交” |
| 3 已下架 | 删除（不可编辑） | 展示下架原因 + “等待管理员恢复或删除” |

- 编辑不重置 `published_at`；编辑后内容立即可见（状态 0），审核拒绝后再次隐藏。

- 审核结果没有推送通知；客户端在“我的帖子”下拉刷新或重新进入时获取最新状态。
- 公开 Feed / 搜索只展示 `status IN (0,1) AND is_deleted=0`；作者本人通过“我的帖子”查看审核拒绝 / 已下架状态。

### 11.2 抢购异步状态

```
POST 抢购 → 202 QUEUED → 轮询 /seckill/activities/{activityId}/my-order
                           ├─ CREATED          → 跳转订单详情 / 支付
                           ├─ CLOSED           → 订单已超时关闭
                           └─ NOT_PARTICIPATED → 失败已回滚资格，可重新抢购
```

- 客户端不要在 `QUEUED` 时重复发起抢购；重复 POST 不会重复扣库存，会返回当前状态（`200`）。
- 轮询间隔 500ms 起，指数退避至 2s，最多 15 秒；之后提示“结果确认中”，可手动刷新。
- 订单创建后 30 分钟未支付自动关闭（服务端延迟消息），客户端展示倒计时；一人一单，关闭后不释放该用户的抢购资格。

### 11.3 计数一致性

| 计数 | 来源 | 一致性 |
|---|---|---|
| 点赞数 | MySQL 计数列 | 强一致（与点赞同事务） |
| 评论数 | MySQL 计数列 | 强一致（与评论同事务） |
| 收藏数 | MySQL 计数列 | 强一致（同步事务） |
| 浏览数 | Redis 累加 + 定时落库 | 分钟级最终一致 |
| 关注 / 粉丝数 | MySQL 计数列 + 缓存 | 秒级最终一致 |

客户端以接口返回值为准做乐观更新；下一次刷新会收敛。

### 11.4 搜索降级

- 正常：ES 返回相关度排序 + 高亮；
- ES 不可用：HTTP 200 + `degraded=true`，返回热榜 / 最新帖子；
- 前端展示“搜索服务暂时不可用，已为你展示热门内容”的提示，不阻断浏览。

### 11.5 SSE 中断

- 用户点击停止 → `AbortController.abort()`；
- 服务端取消上游调用，不再计费；
- 客户端**不得自动重连** SSE；重试必须由用户主动触发，避免重复生成与重复计费。

## 12. OpenAPI 与工程约定

### 12.1 在线文档

- 使用 Knife4j + OpenAPI 3；
- 访问路径：`/doc.html`；
- 已导出可导入 Apifox 的静态契约：[apifox/glimmer-openapi.json](apifox/glimmer-openapi.json)（OpenAPI 3.0，63 个接口，含鉴权、通用 DTO、错误码与示例；导入说明见 [apifox/README.md](apifox/README.md)）；
- 分组：`auth`、`user`、`post`、`interaction`、`seckill`、`ai`、`admin`；
- 每个接口标注：`summary`、`description`、鉴权类型（默认登录 / 白名单 / ADMIN）、错误码；鉴权由全局拦截器实现，不在 Controller 加注解；
- DTO 使用 `@Schema` 描述字段与示例。

### 12.2 DTO 与序列化

- BIGINT 统一 `@JsonSerialize(using = ToStringSerializer.class)`；
- 时间统一返回 epoch 毫秒（`Long`），不使用 `LocalDateTime` 直接序列化；
- 金额使用 `BigDecimal`，序列化为字符串；
- 全局 `spring.jackson.default-property-inclusion=non_null`；
- 枚举在 DTO 中转换为字符串（`USER` / `ADMIN`、`QUEUED` / `CREATED` 等），数据库仍存数字。

### 12.3 契约测试

- 每个模块至少覆盖：成功、参数错误、未登录、越权、状态冲突；
- 秒杀：售罄、超限、重复抢购、轮询到 `CREATED`、关单后 `CLOSED`；
- 审核：通过、拒绝、下架、恢复、自己操作自己被拒；
- AI：正常流、上游报错、用户中断；
- 搜索：正常、ES 降级。

### 12.4 版本与兼容

- `/api/v1` 内只做向后兼容的新增字段；
- 删除字段、改变语义、改变必填性属于破坏性变更，升 `/api/v2`；
- 客户端必须忽略未知字段。
